ABC 移动端 Chrome 精简 — 交互原型

方案核心：移动端（≤768px，沿用现有断点）整条移除顶部 tab 栏（-38px），改为在地址栏左侧放一个 Tabs 按钮；点击后从顶部展开全宽 tab 列表面板（与移动端现有 owner/actor 面板的 fixed 全宽模式一致）。元素选取按钮收进右侧 ⋮ 菜单（菜单里本就有 “Select elements” 项）。桌面端完全不变。四台机器均可在浏览器里直接点按体验。

变体：tab 列表从底部弹出（更接近手机浏览器习惯、拇指可达）— 点 Tabs 按钮展开；遮罩点击关闭。若你偏好这个形态我们就用它

改动点

  • 移除 .browser-tabstrip（移动端 display:none 即可，DOM 保留供状态同步）→ chrome 高度从 ~96px 降到 ~58px，可视面积 +38px。
  • 新增 Tabs 按钮：放在后退按钮左侧（topbar 第一个元素），叠层方块图标 + 当前 tab 数量角标；仅 ≤768px 显示，桌面端隐藏。
  • Tab 面板：fixed 全宽下拉（复用移动端 actor/owner 面板同款定位 top:56~60px, left/right:8px），行 = 标题 + URI + 关闭 ×，底部 “＋ New tab”。当前 tab 高亮。
  • 隐藏元素选取按钮（data-browser-picker-toggle）→ 功能仍在 ⋮ 菜单 “Select elements”（mobileOnly 项已存在）。
  • 断点沿用 ≤768px，桌面端 tab 栏、picker、菜单完全不变。

待你确认

  • Q1 面板形态：顶部全宽下拉（方案 C，与现有移动端面板一致）还是 底部弹出 sheet（变体 D，拇指更近）？
  • Q2 Tabs 按钮是否保留数量角标？（去掉也行，纯图标更干净）
  • Q3 Pin / Rename / “Reopen closed tab” 等 tab 操作移动端本轮不做（桌面端右键菜单保留）；需要的话可加长按或行尾 ⋯ 菜单，另算一轮。
  • Q4 品牌位（地球 icon + Bot Browser 名）随 tabstrip 一并移除，移动端是否接受？
